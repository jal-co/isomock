# Authored-state migration

When an app changes its authored value representation, declare a synchronous pure `authoredStateMigration` alongside `defaults`. Runtime invokes it for admitted source defaults (versions 1 and 2), current local persistence and settings import, before values and keyframes reach their canonical readers. It also validates current source captures, so migration must be idempotent: return canonical values unchanged. App identity and supported envelope versions are checked first; the callback cannot make a different app or unsupported format importable. Local persistence keeps its existing app-scoped key and version authority.

The exported `ToolcraftAuthoredStateMigration` receives `{ source, sourceVersion, values, canvas, timeline }`. `source` is `"defaults"`, `"persistence"` or `"settings"`. `canvas` contains saved `mode` and pixel `size`, with schema defaults when absent; it is context only. `timeline` is the raw timeline record before keyframe normalization, or `undefined` for parameter-only defaults. Return `{ values }` to preserve the timeline, or `{ values, timeline }` to translate legacy keyframe addresses. Settings still require their existing portable timeline shape and do not gain keyframe tracks.

For migrated version 1 defaults, non-control values must be declared in `persistence.additionalValueTargets` or `settingsTransfer.additionalValueTargets`. Runtime retains them in its existing source-default baseline so initial values, Reset, persistence and settings agree. Version 1 keeps parameter Reset scope and does not author a theme or reset the playhead/panels. Undeclared extra values still reject; apps without migration retain the original version 1 control-only admission.

Inputs and outputs are copied finite plain data; input objects are recursively frozen. Never read storage, mutate the input, retain runtime state, perform IO or use randomness/time to create identities. Derive stable IDs deterministically from the admitted legacy representation. Throw when legacy data cannot be migrated faithfully, including unsupported animated addresses. Runtime rejects failed migrations before applying settings or preparing assets. Canonical validation still rejects malformed keyed collections and invalid source defaults after migration; the callback does not replace a codec or the state owner. Apps without this hook keep their existing reader behavior. Live commands already use canonical values and do not invoke migration.
